# AI 가족 운영 에이전트 — 비기능 요구사항 명세서 (Non-Functional Requirements Specification)

> 본 문서는 `PRD_MVP_AI가족운영에이전트.md`, `유스케이스다이어그램.md`, `유스케이스명세서.md`, `기능요구사항명세서.md`의 내용을 근거로, 성능·보안·개인정보·안정성·사용성·접근성 관점에서 시스템이 만족해야 할 품질 기준을 정의합니다.
> 모든 요구사항은 가급적 측정 가능한 수치 기준을 포함합니다.

---

## 1. 성능 (Performance)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-001 | 성능 | 돌봄 정보 등록(텍스트) 시 Family Inbox 구조화 결과가 신속히 반환되어야 한다 | 응답 시간 P95 ≤ 3초 |
| NFR-002 | 성능 | 사진(가정통신문 등) 기반 돌봄 정보 등록 시 OCR 처리 및 구조화가 신속히 완료되어야 한다 | 응답 시간 P95 ≤ 5초, OCR 인식 정확도 ≥ 90% |
| NFR-003 | 성능 | 개인 일정 등록/변경 후 돌봄 일정과의 충돌 감지가 신속히 수행되어야 한다 | 등록 완료~충돌 판정 결과 생성까지 P95 ≤ 60초 |
| NFR-004 | 성능 | 주요 이벤트(등록·조율·인수인계·완료) 발생 시 ThinQ 앱/가전 알림이 지연 없이 전달되어야 한다 | 이벤트 발생~기기 수신까지 P95 ≤ 5초 |
| NFR-005 | 성능 | 가족(최대 8인) 동시 사용 시에도 서비스는 원활하게 동작해야 한다 | 부하테스트 기준 초당 50 요청(RPS) 처리, 오류율 < 1% |
| NFR-026 | 성능 | AI 채팅(UC-04a)의 무료 토큰 사용량 카운팅은 실시간으로 정확히 반영되어야 한다 | 토큰 집계 오차율 0%, 대화 완료~카운팅 반영 지연 ≤ 1초, 매일 00:00 정시 초기화 성공률 100% |
| NFR-028 | 성능 | 사진(OCR) 등록(UC-02)의 무료 일일 사용 횟수(1일 2회) 카운팅은 실시간으로 정확히 반영되어야 한다 | 카운팅 오차율 0%, 등록 완료~카운팅 반영 지연 ≤ 1초, 매일 00:00 정시 초기화 성공률 100% |

## 2. 보안 (Security)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-006 | 보안 | 가족 데이터(일정, 위치, 자녀 정보 등)는 전송·저장 전 구간에서 암호화되어야 한다 | 전송 구간 TLS 1.2 이상, 저장 구간 AES-256 |
| NFR-007 | 보안 | 초대받지 않은 사용자는 가족 데이터에 접근할 수 없어야 한다 | 모의 침투테스트에서 미인가 접근 성공률 0% |
| NFR-008 | 보안 | 로그인은 안전한 인증 방식(소셜 로그인 또는 2단계 인증)을 지원해야 한다 | OAuth 2.0/OIDC 표준 준수, 비밀번호 로그인 시 2단계 인증 옵션 제공 |
| NFR-009 | 보안 | 정보 공개 권한(FR-002) 설정을 위반해 권한 없는 구성원에게 정보가 노출되어서는 안 된다 | 권한 검증 테스트 케이스 통과율 100% |
| NFR-022 | 보안 | 결제·구독 정보 처리는 안전한 결제 표준을 준수해야 한다 | PG사 또는 앱스토어 인앱결제 표준 연동, 카드 원본정보 자체 저장 0건(비저장 원칙, PCI-DSS 준수 사업자 이용) |
| NFR-023 | 보안 | 무료 플랜 사용자가 유료 기능(긴급 도움 요청, 음성 긴급 요청 입력, 가전 알림, 부가 서비스 등)에 우회 접근할 수 없어야 한다 | 유료 기능 접근 제어 테스트 케이스 통과율 100% |

## 3. 개인정보 (Privacy)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-010 | 개인정보 | 아동 관련 개인정보(사진, 위치, 건강·특이사항 등)는 개인정보보호법 및 아동 개인정보 처리 기준을 준수해 처리해야 한다 | 개인정보 영향평가(PIA) 통과, 연 1회 재평가 |
| NFR-011 | 개인정보 | 사용자는 본인 및 자녀와 관련된 데이터의 열람·정정·삭제를 요청할 수 있어야 한다 | 삭제 요청 접수 후 영업일 기준 5일 이내 처리 완료 |
| NFR-012 | 개인정보 | 가족 데이터는 명시적 동의 없이 제3자에게 판매·공유되지 않아야 한다 | 데이터 처리방침 문서화 및 외부 반출 이력 연 1회 감사 |
| NFR-025 | 개인정보 | 패밀리 앨범에 업로드된 자녀 사진은 초대된 가족 구성원만 접근할 수 있어야 한다 | 권한 외 접근 시도 차단율 100% |

> NFR-024(돌봄 동선 확인을 위한 위치정보 수집 동의)는 관련 기능(FR-024·025, UC-05a)이 개인정보 최소화를 위해 서비스 범위에서 제외되면서 함께 결번 처리되었습니다.

## 4. 안정성 (Reliability & Availability)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-013 | 안정성 | 서비스는 높은 가용성을 유지해야 한다 | 월간 가용성 ≥ 99.5% (월 다운타임 ≤ 3.6시간) |
| NFR-014 | 안정성 | 외부 시스템(캘린더, ThinQ) 연동 실패 시에도 사용자 입력 데이터가 유실되지 않아야 한다 | 연동 장애 시 데이터 유실률 0%, 지수 백오프 방식 최대 3회 재시도 |
| NFR-015 | 안정성 | 알림 발송 채널 장애 시 대체 채널로 자동 전환되어야 한다 | 1차 채널 실패 후 10초 이내 대체 채널 전송 성공률 ≥ 95% |

## 5. 사용성 (Usability)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-016 | 사용성 | 별도 교육 없이도 돌봄 정보 등록을 완료할 수 있어야 한다 | 사용성 테스트 태스크 완료율 ≥ 90%, 평균 소요 시간 ≤ 1분, 3단계 이내 |
| NFR-017 | 사용성 | 음성 등록 기능은 한국어 자연어 명령을 정확히 인식해야 한다 | 음성 인식 오류율(WER) ≤ 10% |
| NFR-018 | 사용성 | 알림 문구는 수신자 역할에 맞게 간결하게 요약되어 제공되어야 한다 | 알림 1건당 평균 100자 이내, UX 리뷰 통과 |
| NFR-027 | 사용성 | 무료 사용자가 유료 기능에 접근할 때, 어떤 기능이 유료이며 무엇을 제공하는지 명확히 안내해야 한다 | 안내 문구 50자 이내 핵심 전달, UX 리뷰 통과 |

## 6. 접근성 (Accessibility)

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-019 | 접근성 | 모바일 앱은 국제 웹 접근성 기준을 준수해야 한다 | WCAG 2.1 AA 수준 자동 진단 통과율 ≥ 95% |
| NFR-020 | 접근성 | 가전을 통한 청각 알림은 고령 사용자(조부모 등)도 인지할 수 있는 속도·음량으로 제공되어야 한다 | 발화 속도 ≤ 4음절/초, 기본 음량 60dB 이상 설정 지원 |
| NFR-021 | 접근성 | TV 등 화면 기반 시각 알림은 고대비 모드를 지원해야 한다 | 텍스트-배경 명도 대비비 ≥ 4.5:1 (WCAG AA 기준) |
