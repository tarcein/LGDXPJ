# AI 가족 운영 에이전트 — 유스케이스 명세서

> 본 문서는 `유스케이스다이어그램.md`에 정의된 핵심 운영 흐름(UC-01~UC-07 및 확장 유스케이스)과 부가 서비스(UC-08~UC-10)를 근거로 작성되었습니다.
> 세부 UI 입력 절차(버튼 위치, 화면 전환 등)는 제외하고, **사용자 행동과 시스템 반응이 구분되는 상호작용 단위**로 기술했습니다.
> 외부 시스템(LG ThinQ 플랫폼, 캘린더 시스템) 연동 실패나 권한 문제는 예외 흐름에 포함했습니다.
> **무료/유료 구분**이 있는 유스케이스는 목적·사전조건·예외 흐름에 이를 명시했습니다.

## UC-01. 개인 일정 등록

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-01 |
| **유스케이스명** | 개인 일정 등록 (무료) |
| **액터** | 부모, 돌봄 참여 가족 (주액터) / 캘린더 시스템 (보조 액터) |
| **목적** | 근무 등 개인 일정을 수기로 등록해 캘린더와 동기화하고, 이후 돌봄 일정과의 충돌 감지(2차 조율)의 기반 데이터를 마련한다 |
| **사전 조건** | 사용자가 가족 그룹에 로그인되어 있어야 한다 / 캘린더 시스템 연동이 완료되어 있어야 한다 |
| **사후 조건** | 등록된 개인 일정이 시스템과 캘린더에 동기화되어 저장되며, 이후 돌봄 일정과 비교 가능한 상태가 된다 |
| **기본 흐름** | 1. 사용자가 개인 일정을 수기로 입력한다<br>2. 시스템은 입력 내용을 일정 정보(날짜·시간·내용)로 해석한다<br>3. 시스템은 해석된 일정을 캘린더 시스템과 동기화한다<br>4. 시스템은 등록 완료를 사용자에게 확인해준다 |
| **대안 흐름** | A1. 캘린더 시스템에 이미 등록된 일정이 변경된 경우: 시스템이 변경 사항을 수신해 자동 반영한다<br>A2. 음성으로 등록하려는 경우: UC-01a(유료)로 분기한다 |
| **예외 흐름** | E1. 캘린더 시스템 연동 실패(외부 API 오류): 시스템은 동기화 실패를 알리고 임시 저장 후 재시도 옵션을 제공한다<br>E2. 캘린더 접근 권한 없음: 시스템은 권한 재요청을 안내한다 |
| **관련 기능 요구사항 후보** | 캘린더 연동 API, 일정 파싱 엔진 |

## UC-01a. 음성으로 일정 등록

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-01a |
| **유스케이스명** | 음성으로 일정 등록 (무료, AI 채팅 경유) |
| **액터** | 부모, 돌봄 참여 가족 |
| **목적** | AI 채팅(UC-04a)의 음성 인식을 통해 간편하게 개인 일정을 등록한다 (예: "나 오늘 몇 시에 회의 잡혔어") |
| **사전 조건** | 사용자가 AI 채팅 화면에 접근 가능해야 한다(로그인) / 마이크 접근 권한이 허용되어 있어야 한다 |
| **사후 조건** | 음성으로 전달된 일정이 텍스트로 변환되고 등록 의도가 인식되면 UC-01의 등록 절차로 자동 반영된다 |
| **기본 흐름** | 1. 사용자가 AI 채팅 화면에서 음성 버튼을 눌러 일정을 말한다<br>2. 시스템은 음성을 텍스트로 변환한다<br>3. 시스템은 변환된 텍스트에서 일정 등록 의도를 인식해 UC-01의 등록 절차로 전달한다<br>4. 시스템은 등록된 일정 내용을 채팅 답변으로 사용자에게 확인시킨다 |
| **대안 흐름** | A1. 인식 결과가 일부만 정확한 경우: 사용자가 채팅으로 정정을 요청하거나 일정 화면에서 직접 수정한다 |
| **예외 흐름** | E1. 당일 AI 채팅 무료 토큰 한도를 초과한 경우: UC-04a E1과 동일하게 유료 전환 안내를 표시한다<br>E2. 음성 인식 실패·모호한 표현: 시스템은 재입력 또는 텍스트 확인을 요청한다<br>E3. 마이크 권한 없음: 시스템은 권한 설정을 안내한다 |
| **관련 기능 요구사항 후보** | 음성인식(STT) 엔진, 자연어 이해(NLU), AI 채팅 토큰 사용량 카운팅(FR-018 공용) |

> **(변경)** 초기 기획 시에는 개인 일정 등록 화면(S4)에 별도의 유료 음성 입력 버튼을 두는 구조였으나, 실제 구현에서는 AI 채팅(UC-04a)의 음성 인식 결과를 자연어로 해석해 일정을 자동 등록하는 방식으로 통합되었습니다. 이에 따라 별도의 유료 게이트 없이 AI 채팅과 동일한 무료 토큰 한도 내에서 이용할 수 있습니다.

## UC-02. 돌봄 정보 등록

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-02 |
| **유스케이스명** | 돌봄 정보 등록 |
| **액터** | 부모, 돌봄 참여 가족 |
| **목적** | 자녀 돌봄 관련 정보(등하원, 준비물, 학사일정 등)를 일정/할 일 단위로 구조화해 등록한다 (Family Inbox) |
| **사전 조건** | 사용자가 소속된 가족 그룹이 생성되어 있어야 한다 |
| **사후 조건** | 등록된 돌봄 정보가 일정·준비물·해야 할 일·변경사항으로 구조화되어 가족 공용 데이터에 반영되며, 1차 조율(UC-03)의 입력 데이터로 활용 가능해진다 |
| **기본 흐름** | 1. 사용자가 돌봄 관련 정보를 입력한다(텍스트/사진/음성)<br>2. 시스템은 입력 내용을 일정·준비물·할 일·변경사항으로 구조화한다<br>3. 시스템은 구조화된 정보를 가족 공용 데이터에 반영한다<br>4. 시스템은 등록 완료를 사용자에게 확인해준다 |
| **대안 흐름** | A1. 사진(가정통신문 등)으로 등록하는 경우: 이미지에서 텍스트를 인식해 동일하게 구조화한다(**1일 2회까지 무료**)<br>A2. 기존 등록 정보를 수정하는 경우: 기존 항목을 불러와 변경된 부분만 갱신한다 |
| **예외 흐름** | E1. 입력 내용에서 일정 요소를 인식하지 못한 경우: 시스템은 사용자에게 추가 확인을 요청한다<br>E2. 이미지 인식(OCR) 실패: 시스템은 수동 입력을 안내한다<br>E3. 기존 항목과 중복되는 정보가 감지된 경우: 시스템은 중복 여부를 알리고 병합 여부를 확인한다<br>E4. 사진(OCR) 등록 무료 일일 한도(2회)를 초과한 경우: 시스템은 유료 전환을 안내하고, 텍스트 입력(무제한)으로 유도한다 |
| **관련 기능 요구사항 후보** | Family Inbox 구조화 엔진, OCR/이미지 인식, 음성인식(STT), OCR 일일 사용량 카운팅(구독 상태 확인 연동) |

## UC-03. 가족 역할·할일 조율 (1차 조율)

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-03 |
| **유스케이스명** | 가족 역할·할일 조율 (1차 조율) |
| **액터** | 부모, 돌봄 참여 가족 |
| **목적** | 등록된 일정·돌봄 정보를 근거로 가족별 기본 역할과 할 일을 자동으로 배정한다 (Role Match) |
| **사전 조건** | 돌봄 정보(UC-02)가 최소 1건 이상 등록되어 있어야 한다 / 가족 구성원별 기본 역할·가용 정보가 설정되어 있어야 한다 |
| **사후 조건** | 담당자별 할 일이 배정되어 각 가족 구성원에게 표시되며, 배정 결과가 알림 제공(UC-07)의 대상이 된다 |
| **기본 흐름** | 1. 시스템은 새로 등록된 돌봄 정보와 가족의 기존 역할 패턴을 비교한다<br>2. 시스템은 해당 일자에 필요한 역할(픽업, 준비물 등)을 담당자별로 배정한다<br>3. 시스템은 배정 결과를 관련 가족 구성원에게만 전달한다<br>4. 사용자는 배정 결과를 확인한다 |
| **대안 흐름** | A1. 사용자가 자동 배정 결과를 직접 수정하는 경우: 담당자를 변경하면 시스템이 이를 반영하고 관련자에게 재통보한다 |
| **예외 흐름** | E1. 배정 가능한 담당자가 없는 경우(전원 일정 충돌): 시스템은 2차 조율(UC-04)로 전환한다<br>E2. 가족 구성원의 역할 정보가 설정되어 있지 않은 경우: 시스템은 기본 역할 설정을 요청한다 |
| **관련 기능 요구사항 후보** | Role Match 자동 배정 알고리즘, 가족 구성원 프로필/역할 관리 |

## UC-04. 대안 추천 및 승인 (2차 조율)

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-04 |
| **유스케이스명** | 대안 추천 및 승인 (2차 조율) |
| **액터** | 부모, 돌봄 참여 가족 |
| **목적** | 예외 상황에서 대안을 추천하고, 부모의 승인을 거쳐 재조율한다 (Exception Care). 진입 경로는 두 가지이며(① 시스템의 자동 충돌 감지, ② 사용자의 긴급 도움 요청), 실제로는 서로 다른 절차로 처리된다 — ①은 대체 담당자 승인 방식, ②는 선착순 응답 방식이다 |
| **사전 조건** | 개인 일정(UC-01)과 1차 조율 결과(UC-03) 간 충돌이 자동 감지되었거나, 긴급 도움 요청(UC-04b)이 접수된 상태여야 한다 |
| **사후 조건** | 변경된 담당자·일정이 확정되어 가족에게 반영되며, 관련 알림(UC-07)이 발송된다 |
| **기본 흐름** | **① 자동 충돌 감지 경로**: 1. 시스템은 개인 일정과 돌봄 일정 간 충돌을 자동 감지한다<br>2. 현재 담당자가 대체 담당자 1명과 사유를 지정해 대안을 제안한다<br>3. 부모(주돌봄자)는 제안된 대안을 확인하고 승인한다<br>4. 시스템은 승인된 대안으로 역할 배정을 갱신한다<br>**② 긴급 도움 요청 경로**: 1. 사용자가 긴급 도움 요청(UC-04b)을 등록한다<br>2. 시스템은 선택한(또는 전체) 가족 구성원에게 즉시 알림을 보낸다<br>3. 가장 먼저 응답한 구성원이 별도 승인 없이 바로 담당자로 확정된다 |
| **대안 흐름** | A1. 부모가 대안을 거절하는 경우(①): 시스템은 다른 대안을 재추천하거나 수동 조정을 안내한다<br>A2. 가족이 AI에게 자연어로 질의해 대안을 요청하는 경우: UC-04a로 분기한다<br>A3. 긴급 요청에 아무도 응답하지 않는 경우(②): 요청자 또는 주돌봄자가 요청을 취소할 수 있다 |
| **예외 흐름** | E1. 추천 가능한 대안이 없는 경우(①): 시스템은 돌봄 공백 발생을 알리고 수동 조율을 요청한다<br>E2. 부모가 15분 내 응답하지 않는 경우(①): 시스템은 담당자에게 재알림을 1회 발송한다(다단계 에스컬레이션 아님)<br>E3. 대안 추천 엔진/외부 데이터 조회 실패: 시스템은 추천 실패를 알리고 수동 조율 화면으로 전환한다 |
| **관련 기능 요구사항 후보** | Exception Care 충돌 감지·대안 추천 엔진, 단일 재알림 로직, 승인 워크플로우, 긴급 요청 선착순 확정 로직 |

## UC-04a. AI 채팅

| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-04a |
| **유스케이스명** | AI 채팅 (무료 1일 50,000 토큰 / 유료 1일 200,000 토큰) |
| **액터** | 부모, 돌봄 참여 가족 |
| **목적** | 가족이 능동적으로 AI 에이전트에게 텍스트 또는 음성으로 자연어 질의를 하여 일정을 확인·등록·변경하거나 대안을 요청한다 (2차 조율의 확장이자 UC-01a 음성 일정 등록의 실행 경로) |
| **사전 조건** | 사용자가 로그인되어 있어야 하며, 가족 일정 데이터가 조회 가능한 상태여야 한다 |
| **사후 조건** | 질의에 대한 답변 또는 조치 제안이 제공되며, 일정 등록/변경 의도가 인식된 경우 즉시 반영되고, 예외 상황 대안 제안은 사용자가 승인하면 UC-04의 갱신 흐름으로 이어진다. 해당 대화에서 소모한 입력+출력 토큰이 당일 사용량에 차감된다 |
| **기본 흐름** | 1. 사용자가 AI 에이전트에게 텍스트 또는 음성으로 질문·요청을 입력한다(예: "이번 주 충돌 있어?", "내일 3시에 회의 등록해줘")<br>2. 시스템은 당일 토큰 한도(무료 50,000 / 유료 200,000) 잔여량을 확인한다<br>3. 시스템은 질의 의도를 해석하고 가족 일정 데이터를 조회한다<br>4. 시스템은 답변·조치 제안을 응답하며, 일정 등록/변경 의도가 있으면 개인 일정에 즉시 반영한다<br>5. 시스템은 해당 대화의 토큰 사용량을 당일 사용량에 반영한다<br>6. 예외 상황 대안 제안에 대해 사용자가 승인하면 UC-04의 갱신 절차로 연결된다 |
