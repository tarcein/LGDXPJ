# 프론트 변경사항 및 백엔드 인계 보고서

작성일: 2026-09-15 · 대상: LGDXPJ 로컬 개발 목업

이 문서는 지금 동작하는 코드와 아직 화면 체험에 머무는 기능을 구분한 작업 인계 자료다. 신규 API 경로와 응답 형태는 아래에서 **제안**으로만 표시하며, 확정된 계약은 [개발_계약.md](../개발_계약.md)이다. 인증과 아동 데이터 보호가 없는 현재 데모에는 실제 가족 정보를 입력하거나 외부 배포를 해서는 안 된다.

> 이 문서는 백엔드 추가 작업 이전에 작성했다. AI 채팅·OCR·음성·가족방 등 **현재 구현된 API와 프론트 연결 작업**은 [백엔드→프론트 인계](백엔드변경_프론트인계.md)를 기준으로 확인한다.

## 1. 이번 프론트 변경

| 영역 | 구현된 변경 | 서버 연동 상태 |
|---|---|---|
| ThinQ 전역 내비게이션 | 홈·디바이스·케어·메뉴를 가족 기능에서 분리하고, 가족 탭 안에 오늘·돌봄 정보·역할 배정·일정 및 전체 기능 진입점을 배치. 팀 제공 asset 아이콘 사용 | 디바이스·케어·메뉴는 기존 ThinQ 앱 연동 전 목업 |
| ThinQ 홈 가족 카드 | ZIPPY 요약, 확인 건수, 아이별 돌봄 제목을 초기 데이터와 재조회 결과로 표시 | GET /api/bootstrap 데이터 사용. 로컬 액션 후 재조회하면 갱신 |
| 가족 FAB | 탭/길게 누르기로 알림장 촬영·일정 직접 입력·케어 어시스턴트·긴급 도움 요청 4개 동작 노출 | 첫 두 화면은 기존 API 경로로 이어짐. 뒤 두 화면은 체험 |
| 알림장 등록 | 사진 촬영 버튼은 모바일 후면 카메라 입력을 요청하고, 사진 업로드 버튼은 일반 파일 선택을 연다. 두 경로 모두 로컬 미리보기 | **사진 파일은 서버로 전송되지 않음. OCR 없음.** 내용 직접 입력 후 JSON POST /api/intakes |
| AI 채팅 진입 | 가족 홈/FAB에서 접근, 질문 입력과 현재 데모 데이터의 규칙형 요약 | 실제 LLM·대화 저장·토큰 집계 없음 |
| 온보딩 | 소개 → 역할 선택 → 아이 선택을 직접 눌러볼 수 있음 | 선택은 가족 그룹/계정으로 저장되지 않음. 기존 ThinQ 로그인·초대 연결 없음 |
| Free/Pro 전환 | 플랜 화면에서 화면 체험 모드를 바꾸고 브라우저 localStorage에 기억. Pro 표시 및 가전 알림 체험 UI | **서버 family_group.plan은 변경되지 않음.** 결제·관리자 권한 없음 |
| 확장 화면 | 긴급 요청 미리보기, 미배정 항목 탐색, 로컬 앨범, 제도 선택 등 클릭 가능 | 실제 브로드캐스트·예측·사진 저장·지역 조회 없음 |

변경 코드: [App.tsx](../../frontend/src/App.tsx), [api.ts](../../frontend/src/api.ts), [index.css](../../frontend/src/index.css), [모바일 클릭 검사](../../frontend/scripts/visual-check.mjs), [루트 README](../../README.md). 제공 아이콘은 저장소의 asset/에서 직접 가져오므로 팀 커밋에 asset/도 포함해야 한다. 현재 커밋은 하지 않았다.

검증: 프론트 빌드·린트 통과. Edge 모바일 크기 클릭 검사에서 전역/가족 탭, FAB 네 가지 항목, 채팅 입력, Pro 체험 전환, 온보딩, 홈 요약 재조회, 촬영·업로드 파일 입력과 미리보기를 확인했다. 홈 갱신 검사는 모의 API 응답을 사용하여 DB를 변경하지 않았다. **실제 모바일 기기 카메라 권한·촬영은 아직 실기기 검증 전이다.**

## 2. 기존 백엔드에서 이미 되는 것과 막히는 지점

- 실제 저장 흐름: 텍스트 돌봄 정보 등록·확인, 수기 일정, 담당 제안·요청·수락, 예외 대안, 인수인계 확인, 완료·메모, DB 알림 기록·읽음, 구성원/아이 등록과 정보 공개 권한. 경로는 [개발_계약.md](../개발_계약.md#http-api)를 따른다.
- 백엔드 [main.py](../../backend/app/main.py)는 단일 demo-family ID를 사용하고 GET /api/bootstrap에서 가족 전체 데이터를 반환한다. 현재 인증·다중 가족 격리·요청자별 권한 필터는 없다.
- [db.py](../../backend/app/db.py)의 family_group.plan은 FREE 기본값인 단일 문자열이다. POST /api/members는 FREE에서 상태가 REMOVED가 아닌 구성원 3명 이상이면 403, POST /api/children은 FREE에서 자녀 2명 이상이면 403을 반환한다. 초기 데모 데이터가 이미 이 한도에 도달하므로 화면을 Pro로 바꿔도 추가 등록은 실패한다. 플랜 변경 API와 구독·결제 테이블은 현재 백엔드에 없다.
- POST /api/intakes는 JSON raw_content 필수, input_type은 TEXT 또는 PHOTO_TRANSCRIPT만 허용한다. 현재 사진을 선택한 뒤 사용자가 직접 입력한 문장을 PHOTO_TRANSCRIPT로 보낼 수 있지만 **이 값은 OCR 성공이나 사진 저장을 증명하지 않는다.** care_intake에는 파일 참조가 없다.
- 앱 알림은 notification 테이블 기록이며 ThinQ 푸시나 가전 전달이 아니다. 캘린더 연동·실제 LLM·사용량 집계·긴급 요청·앨범·위치·음성 파일 API도 없다.

## 3. 백엔드 작업 권장 순서

우선순위는 팀 작업 순서 제안이다. PRD의 MVP Phase 1과 Post-MVP, 그리고 실제 서비스 배포 안전성은 별개로 판단했다.

| 우선 | 작업/연관 요구사항 | 백엔드 완료 기준 | 프론트·팀 연결 |
|---|---|---|---|
| P0 | 인증, 가족 생성·초대·수락, 요청자별 가족·권한 검사 (FR-001~002, NFR-007~009) | 고정 demo-family 제거; 본인 가족만 조회/변경; 초대 수락 전 접근 차단; bootstrap에서 권한 밖 아동·위치·건강 데이터 제외 | ThinQ 로그인 담당과 계정 식별자/토큰 계약 확정. 온보딩 선택값을 실제 요청으로 연결 |
| P0 | 실제 플랜 및 관리자 테스트 전환 (FR-003~004, NFR-023) | 서버가 검증된 FREE/유료 상태를 반환하고 모든 유료 기능과 인원 제한을 서버에서 검사. 개발용 관리자 전환은 인증된 관리자·개발 환경에만 허용하고 감사 기록 남김 | 플랜 화면의 localStorage 스위치를 서버 플랜 응답으로 교체. 3명 초과 추가/Free 재전환 테스트 |
| P0 | 사진 수집·OCR·일일 한도 (FR-009~010, NFR-002, NFR-028) | 촬영/업로드 파일을 실제 수신·검증, OCR 텍스트 구조화 후 NEEDS_REVIEW 반환, 실패 시 수기 입력 대체. Free 1일 2회 사용량을 동시 요청에서도 정확히 검사 | 프론트가 사진 파일 multipart 전송으로 변경. 지금의 PHOTO_TRANSCRIPT 표기는 수기 전사와 OCR 결과로 구분 |
| P1 | 외부 캘린더 동기화 (FR-005~006, NFR-014) | 연결·해제·갱신 상태 제공, 실패 재시도, 중복 일정 방지. 가족에게는 필요한 바쁨/한가함만 공개 | Google/Outlook 화면을 실제 연결 상태와 수기 일정 화면에 결합. 제공자 권한 범위는 함께 결정 |
| P1 | ThinQ 앱 알림과 홈 접점 (FR-012, FR-029, NFR-004) | 가족 이벤트를 수신 대상별로 전달하고 전달 실패/재시도 기록. 기존 ThinQ 계정·푸시 인터페이스와 연결 | 가족 카드에는 현재 bootstrap 데이터 재사용 가능. 원래 ThinQ 홈/전역 탭 구현 책임은 호스트 앱 팀과 조정 |
| P2 | AI 채팅과 사용량 (FR-018, NFR-026) | 실제 가족 권한 범위 안에서 답변하고 입력+출력 토큰 및 무료 일일 한도를 서버 집계. 조치 제안은 사용자 승인 전 자동 실행하지 않음 | 규칙형 답변을 API 답변으로 교체하고 남은 사용량·한도 오류 표시 |
| P2 | 긴급 요청·선착순 응답 (FR-019~020) | 유료 상태 검증, 가족 전체 관련자에게 요청, 최초 응답자 1명만 원자적으로 확정, 이후 응답에 마감 안내. 기존 예외 대안 흐름에 연결 | 현재 발송 미리보기 버튼을 실제 요청/응답 상태 화면으로 변경 |
| P2 | 음성, 가전 알림, 완료 사진·앨범, 공백·지역 제도, 동선 (FR-007, 023~025, 027, 030~035) | 각각 파일/기기/위치/지역 연동과 동의·권한·보관기간을 갖춘 뒤 제공 | 화면 체험 데이터를 실제 API 상태로 단계별 교체 |

P0의 인증·가족 격리와 미디어 보호는 로컬 목업을 실제 사용자 서비스로 옮기기 전 안전 조건이다. OCR 공급자 도입이 늦으면 **사진 등록은 수기 전사 대체로 명확히 표시한 채 텍스트 MVP를 먼저 검증**할 수 있다. 다만 사진 촬영→자동 구조화 MVP 성공 시나리오는 그 상태에서 달성했다고 주장할 수 없다.

## 4. API 계약 제안 — 확정 전 프론트·백엔드 공동 결정

| 기능 | 제안 인터페이스/응답 | 기존 계약에서 주의할 점 |
|---|---|---|
| 플랜 조회·전환 | GET /api/bootstrap의 family.plan을 서버 유효 플랜으로 사용. 개발용 관리자 전환이 필요하면 인증된 관리자 전용 별도 경로에서 FREE/유료 코드·변경 사유를 받아 새 유효 플랜과 한도를 반환 | 브라우저 localStorage는 결제/권한 근거로 절대 사용하지 않음. 현재 문자열 비교는 FREE가 아닌 임의 값도 무료 제한을 우회하므로 허용 코드 검증 필요 |
| 사진 OCR | 제안: POST /api/intakes/photo, multipart/form-data의 image와 child_id → intake_id, items[], requires_review, 남은 일일 한도/한도 오류. 재시도 중복 과금을 막을 요청 식별자도 검토 | 현재 [api.ts](../../frontend/src/api.ts)는 JSON Content-Type을 항상 넣으므로 파일 업로드 시 별도 helper가 필요. 기존 텍스트 POST /api/intakes는 유지 |
| 가족 온보딩 | ThinQ 로그인 계정 식별 후 가족 생성, 구성원 초대·수락, 아이 등록, 권한 설정 상태를 돌려주는 계약 | 데모의 구성원/아이 추가 API가 있어도 실제 가족 생성과 초대·권한 검증을 대체하지 못함 |
| AI 질문 | 제안: 가족 컨텍스트가 서버에서 식별되는 메시지 요청 → 대화 ID, 답변, 사용 토큰, 남은 무료 사용량 또는 한도 오류 | 현재 프론트 답변은 규칙형이며 대화 저장 없음. 구성원 ID/가족 ID를 클라이언트 주장만으로 신뢰하지 않음 |
| 긴급 요청 | 제안: 생성/조회/응답 경로를 분리하고 요청 상태, 수신자, 확정 담당자, 종료 시각을 반환 | 기존 POST /api/exceptions는 대안 승인 흐름이며 긴급 브로드캐스트/선착순 확정을 대신하지 않음 |
| 캘린더·ThinQ | 연결 상태·실패 이유·해제 경로와 호스트 앱 푸시 수신자 계약을 먼저 정함 | 인증 토큰/외부 비밀값을 bootstrap이나 브라우저에 노출하지 않음 |

사진에는 파일 형식·크기 제한, OCR 실패 처리, 아동 사진 접근·삭제·보관 기간이 필요하다. 미디어·사용량·구독·동의 객체는 [데이터 객체 정의서](../LG_가족_운영_에이전트_데이터객체정의서_완성.md)의 media_asset, feature_usage_daily, subscription, consent_record를 참고할 수 있지만, **현재 SQLite 데모에 해당 객체가 구현됐다는 뜻은 아니다.** API 응답 키/상태가 확정되면 [개발_계약.md](../개발_계약.md)와 프론트 타입을 함께 갱신한다.

## 5. 문서·UI 간 결정이 필요한 차이

1. **플랜 코드:** 데이터 객체 정의서의 유료 코드 예시는 PREMIUM, 프론트 체험 변수는 PRO, 현재 백엔드 값은 FREE다. 서버·API의 정식 유료 코드를 하나로 확정해야 한다.
2. **Pro 인원 상한:** [PRD Freemium](../PRD_MVP_AI가족운영에이전트.md#12-3-freemium-정책-무료유료-기능-구분)은 Free 보호자 3명·자녀 2명만 정한다. 유료 상한은 명시되지 않았다. NFR의 동시 사용자 최대 8인은 요금제 인원 한도와 다른 지표다. 임의로 8명 제한을 넣지 않는다.
3. **AI 채팅 표기:** [기능요구사항](../기능요구사항명세서.md#11-무료유료-기능-구분-요약)은 FR-018을 Free 1일 10,000 토큰까지, 이후 유료 확장으로 정의한다. 현재 프론트의 PRO 미리보기 문구는 실제 정책과 다르므로 사용량 API 도입 시 무료 진입/잔여량으로 수정해야 한다.
4. **사진 횟수:** FR-009는 OCR 무료 1일 2회, 초과 유료다. 지금 촬영·업로드 **선택 횟수**는 서버 전송/인식이 없어 과금·사용량으로 셀 수 없다. 날짜 경계의 서비스 시간대, 실패·재시도 카운팅 시점을 확정해야 한다.
5. **정보구조 경계:** 기존 [메뉴 구조](../메뉴구조도다이어그램/메뉴구조도.md)는 가족 서비스 자체의 IA이고, 이번 프론트는 그 서비스를 ThinQ 전역의 가족 탭 안에 넣은 목업이다. 원래 ThinQ 홈·디바이스·케어 기능의 실제 코드/권한은 이 저장소 밖의 호스트 팀 계약이 필요하다.
6. **관리자 체험 vs 실제 구독:** 현재 Pro 전환은 모든 데모 사용자에게 보이는 로컬 스위치다. 운영 관리자 권한, 구독 갱신, 결제 검증과는 다르다.
