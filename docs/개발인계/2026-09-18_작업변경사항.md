- 가족 구성원 프로필, 활동 상태, 초대, 역할 선택 화면을 새 에셋과 실제 등록 순서에 맞췄다.

- Pro 안내·결제·잠금 화면과 돌봄 공백 예측·돌봄 제도 화면을 Figma 기준으로 정리했다.

## 4. ThinQ 진입과 공통 화면

### 4.1 ThinQ 홈과 서비스 로딩

- ThinQ 홈의 좌측 상단 홈 선택 영역, 우측 상단 통합 버튼, 하단 탭을 `home_asset` 에셋으로 교체했다.
- 기존 텍스트·기호로 만든 `+`, 알림, 더보기 버튼 대신 전달받은 통합 우측 상단 버튼 이미지를 사용했다.
- ZIPPY 서비스 카드와 플로팅 버튼에 서비스 캐릭터·로고 에셋을 적용했다.
- 서비스 진입 로딩 중 `home_asset/1.png`, `2.png`, `3.png`가 순서대로 도리도리 움직이는 것처럼 전환되도록 구성했다.
- 로딩 진행 색상을 기존 빨강에서 서비스 로고와 어울리는 색으로 조정했다.
- 가족방 데이터가 없거나 삭제된 로그인 토큰이 남아 있는 경우 빈 화면에 멈추지 않고 토큰을 정리한 뒤 개발용 미리보기 데이터로 복구하도록 보완했다.

### 4.2 데스크톱 기능 목록과 모바일 전체 화면

- 데스크톱에서 폰 목업 옆에 화면별 기능 목록이 항상 보이도록 복구했다.
- 기능 목록에서 ThinQ, 홈, 케어, 일정, 가족, 더보기와 세부 화면으로 바로 이동할 수 있다.
- 모바일에서는 기능 목록을 숨기고 앱 셸, 폰 프레임, 루트 요소가 `100dvh`/`100svh`를 사용하도록 조정했다.
- 모바일 브라우저의 상하단 안전 영역을 반영하도록 `viewport-fit=cover`를 추가했다.
- 터치 지원 여부로 데스크톱 기능 목록이 잘못 사라지던 미디어 쿼리를 화면 너비 기준으로 변경했다.
- 390×844 및 393×852 화면에서 앱이 바깥 여백 없이 전체 화면을 채우는 것을 확인했다.

### 4.3 공통 헤더와 아이콘

- 서비스 화면 우측 상단에 알림 아이콘과 현재 로그인한 구성원의 프로필을 다시 표시했다.
- 알림 아이콘 크기를 키우고 프로필은 별도 기본 원 대신 구성원 프로필 색상과 이름 첫 글자를 사용한다.
- 기능 옆 `PRO` 텍스트를 전달받은 Pro 아이콘으로 교체했다.
- 가족, 더보기, 케어 등에서 사용하는 아이콘은 `asset/아이콘`과 각 기능별 에셋 폴더의 이름에 맞춰 적용하고 크기를 조정했다.

## 5. 온보딩과 가족방

### 5.1 가족방 온보딩

- 가족방 온보딩은 ThinQ에서 처음 `지금 만들기`로 진입할 때만 실행하도록 정리했다.
- 더보기 화면의 `가족방 온보딩`, `일정 등록 온보딩` 메뉴를 제거했다.
- 별도 일정 온보딩은 제거하고 일정 등록은 캘린더에서 바로 시작하도록 바꿨다.
- 일정 온보딩의 `무엇까지 공유할까요` 단계를 제거했다.
- 아이를 선택하면 캘린더 연동 단계를 거치지 않고 아이 일정 입력으로 바로 이동한다.
- 역할 선택 화면에서 선택된 역할은 `선택한역할.png`, 선택되지 않은 역할은 `그외의역할.png`를 사용한다.

### 5.2 가족 구성원과 프로필

- 구성원 등록 순서대로 `구성원1`부터 `구성원8`까지의 색상 체계를 적용한다.
- 프로필 안에는 구성원 이름의 첫 글자를 표시한다. 예를 들어 `정희원`은 `정`으로 표시된다.
- 구성원 목록에는 접속 여부에 따라 활동 중·비활동 아이콘을 표시한다.
- 우측 상단의 내 프로필에는 활동 상태 점을 표시하지 않고 내 프로필 색상과 첫 글자만 표시한다.
- 가족 탭의 아이 카드는 학교·책가방 예시 아이콘 대신 `온보딩일정등록/아이_web.png`를 공통으로 사용한다.

### 5.3 가족 초대

- 카카오톡 공유 버튼이 주소 복사로 끝나지 않고 카카오톡 공유 흐름으로 연결되도록 정리했다.
- 가족 탭의 구성원 옆 `+`와 가족 설정의 `+ 초대`를 누르면 스크롤 없이 초대 바텀시트가 바로 열린다.
- 초대 바텀시트에서 역할 선택, 초대 코드, 카카오톡, 문자, 링크 복사, 시스템 공유를 제공한다.
- 가족 생성 중 초대 링크의 생성자 정보가 새 가족방의 주돌봄자로 정확히 저장되도록 백엔드를 수정했다.
- Free 가족의 구성원 제한 안내와 Pro 전환 안내 화면을 연결했다.

## 6. 캘린더와 일정

### 6.1 캘린더 보기와 색상

- 보기 설정을 `전체`, `나`, 등록된 아이 이름별로 구성했다.
- `아이1`, `아이2` 같은 예시 이름을 제거하고 실제 등록된 아이 이름을 사용한다.
- 아이가 늘어나면 동일한 방식으로 필터 항목이 자동 추가된다.
- 일정 색상은 `나`, 아이별 고유 색상, 그 외 돌봄자 색상으로 구분한다.
- 캘린더 아래 선택 날짜 일정 영역은 일정 개수만큼만 늘어나며, 일정이 없을 때 불필요한 고정 높이를 차지하지 않게 했다.
- 주간 시간표는 고정된 14~17시가 아니라 등록된 일정의 가장 이른 시간부터 가장 늦은 시간까지 표시한다.

### 6.2 일정 등록과 루틴 등록

- 캘린더의 `+` 버튼을 누르면 `일정 등록하기`와 `루틴 설정하기`를 선택하는 팝업을 표시한다.
- 일정 등록의 대상 선택 화면에 `온보딩일정등록/본인_web.png`와 `아이_web.png`를 적용했다.
- 루틴 종료 시간 입력란의 안내를 `없으면 비워두기`로 한 칸 안에 모두 표시했다.
- 일정의 종료 시간이 없으면 별도 종료 시각을 강제하지 않는다.
- 반복 일정 수정 시 `이번 일정만 변경`과 `이후 일정 변경`을 선택할 수 있는 확인 화면을 추가했다.
- 반복 패턴이 여러 번 바뀌면 현재 패턴을 기본값으로 반영할지 묻는 제안 화면을 추가했다.

### 6.3 반복 일정 백엔드

- 개인 일정과 아이 일정 수정 API에 `update_scope`를 추가했다.
- `SINGLE`은 선택한 일정 한 건만 변경한다.
- `FUTURE`는 같은 `recurrence_id` 중 선택한 시점 이후 일정을 함께 변경한다.
- 반복 일정 변경 시 시작 시각 이동량과 기존 소요 시간을 이후 일정에 동일하게 적용한다.
- 아이 반복 일정 변경 시 연결된 돌봄 항목과 배정 상태도 함께 갱신하고 담당자에게 재확인 알림을 보낸다.
- API 응답에 `updated_count`와 `recurring_instance_only`를 포함해 프론트가 실제 반영 범위를 확인할 수 있게 했다.

### 6.4 외부 캘린더

- Google과 Microsoft OAuth callback 후 자동으로 일정을 동기화하고 결과 건수를 표시한다.
- 공급자 콘솔에 등록한 정확한 주소를 사용할 수 있도록 `GOOGLE_REDIRECT_URI`, `MICROSOFT_REDIRECT_URI`를 지원한다.
- 별도 URI가 없으면 기존 `CALENDAR_REDIRECT_BASE` 기반 callback 주소를 사용한다.

### 7.3 긴급 도움 요청

- 같은 배정에서 긴급 요청을 한 번만 보낼 수 있던 제한을 제거했다.
- DB의 `idx_emergency_open_assignment` 고유 인덱스를 제거하고 기존 DB에서도 초기화 시 자동 삭제한다.
- 동일 배정에 여러 긴급 요청을 생성할 수 있다.
- 한 요청이 수락되면 같은 배정에 남아 있는 다른 열린 요청은 자동으로 취소된다.
- 긴급 요청 횟수 제한 제거와 중복 요청 수락 정리를 자동화 테스트에 추가했다.

## 8. AI 채팅과 음성 입력

- AI 답변 대기 중 `AI채팅/1.png`부터 `4.png`까지 순서대로 자연스럽게 전환되는 중앙 로딩 애니메이션을 추가했다.
- 답변이 도착하면 로딩 애니메이션이 사라진다.
- 채팅 좌측 상단의 캐릭터를 전달받은 좌측 상단 아이콘으로 교체했다.
- 음성 입력과 전송 버튼을 `AI채팅` 폴더 에셋으로 교체했다.
- 화면의 `음성 녹음` 문구를 사용자가 기능을 이해하기 쉬운 `음성 인식`으로 변경했다.
- 채팅에서 등록한 일정은 ISO 전체 문자열 대신 `19시`, `19시~20시`처럼 필요한 시간 단위만 표시한다.

## 9. 잠금화면

- 잠금화면 안에서 동선 카드가 기기 폭을 벗어나지 않도록 전체 크기를 조정했다.

- 모바일 화면에서도 카드와 배경이 빈 여백 없이 채워지도록 조정했다.

## 10. Pro 플랜과 더보기

### 10.1 Pro 안내와 결제

- 더보기의 `플랜·결제`를 계정 카테고리에서 `혜택·부가서비스` 첫 번째 항목으로 이동했다.
- 사용하지 않는 계정 카테고리를 제거했다.
- Pro 안내 화면은 `프로안내화면` 폴더의 캐릭터, 플랜, 시작 버튼, 무료 차이 설명 에셋을 사용한다.
- 이미지에 포함된 `Pro 시작하기` 문구와 별도 텍스트가 겹치던 문제를 제거했다.
- 무료·Pro 기능 비교는 별도 HTML 문구 대신 `무료차이설명.png`를 배치했다.
- 월간과 연간 버튼을 모두 선택할 수 있고, 연간 선택 시 가격을 `76,000원`으로 표시한다.
- `Pro 시작하기`를 누르면 실제 결제 영역이 열린다.

### 10.2 더보기와 Pro 권한 표시

- 알림함, 알림 설정, 돌봄 공백 예측, 돌봄 제도, 플랜 결제 메뉴에 전달받은 아이콘을 적용했다.
- 서비스 이용약관, 개인정보 처리방침, 로그아웃 글자 크기를 다른 메뉴와 맞췄다.
- Pro 사용자는 혜택·부가서비스 항목이 비활성 색으로 흐려지지 않고 일반 메뉴와 같은 진한 색으로 표시된다.
- Free 사용자가 잠긴 기능을 누르면 Pro 안내 모달을 거쳐 결제 화면으로 이동한다.

## 11. 돌봄 공백 예측과 돌봄 제도

- 돌봄 공백 예측 화면을 위험 기간, 추천 대안, 상세 보기 중심의 Figma 구성으로 정리했다.
- 돌봄 제도 화면에 지역, 맞벌이, 가족돌봄 필터 버튼을 구현했다.
- 상단 필터는 실제로 클릭할 수 있으며 선택된 조건으로 검색한다.
- 한 번 저장한 지역도 상단 지역 버튼이나 `조건과 전체 제도 보기`에서 다시 변경할 수 있다.
- `조건과 전체 제도 보기`를 펼쳐도 폰 화면 가로 폭을 넘지 않도록 입력 폼, 표, 카드 너비를 제한했다.
- 긴 기관명, 주소, 지원 조건, 신청 방법, 문의 내용은 카드 안에서 줄바꿈되도록 했다.
- 상세 화면을 열면 상단으로 이동하고, 하단 `공식 상세 보기`와 `목록으로` 버튼이 AI 플로팅 버튼과 겹치지 않도록 여백을 조정했다.

## 12. 데이터베이스와 개발용 미리보기

- 실제 테스트를 위해 기존 가족방 데이터를 비울 수 있도록 데모 시드 여부를 `LGDX_SEED_DEMO`로 제어한다.
- 데모 데이터가 없는 빈 DB에서도 첫 가족방 생성과 초대 링크 생성이 정상 동작하도록 수정했다.
- 빈 DB에서 첫 가족 생성 후 구성원 추가가 가능한지 테스트를 추가했다.
- 기능 목록으로 각 화면을 확인할 수 있도록 개발용 `demo-family` 데이터를 다시 준비했다.
- 사용자 생성 가족방과 삭제된 세션 토큰은 개발용 미리보기 복구 흐름과 분리한다.
- 브라우저에 삭제된 가족방의 토큰이 남아 있어도 자동으로 제거하고 데모 화면을 불러온다.
