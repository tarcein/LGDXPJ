# 백엔드 변경사항 → 프론트엔드 인계

기준일: 2026-09-15 · 대상: 현재 로컬 백엔드 작업트리와 팀원이 올린 프론트 화면. 백엔드 코드와 이 문서가 포함된 커밋을 받은 뒤 연동한다. 기존 [프론트→백엔드 인계](프론트변경_백엔드인계.md)는 백엔드 추가 작업 **이전**의 현황을 기록한 자료다.

## 프론트 연동 현황 (2026-09-16)

- 완료: 가족방 생성·초대코드 참가와 Bearer 세션, 실제 사진 파일 OCR 업로드와 수기 등록, AI 텍스트·음성 채팅 및 기록 복원, 서버 플랜·기능 조회, 긴급 요청 생성·응답·취소, 인수인계 특이사항 표시·수정과 수신자 확인 버튼.
- 새 가족방의 아이 정보는 가족 설정에서 등록한다. 인증된 사용자는 본인의 할 일·일정만 조작하고, 정보 공개 변경은 주돌봄자에게만 제공한다.
- 남은 작업: ThinQ 계정과 가족방 세션 연결, 실제 결제·구독, Google/Outlook OAuth, ThinQ 푸시·가전, 서버 앨범·돌봄 공백·지원 제도. 개발자 플랜 전환은 비밀 토큰을 브라우저에 넣지 않고 백엔드에서 수동으로 시험한다.
- 아래 표의 `현재 ...` 설명은 **9월 15일 연동 전 스냅샷**이다. 최신 프론트 구현은 [`App.tsx`](../../frontend/src/App.tsx), [`api.ts`](../../frontend/src/api.ts)를 기준으로 확인한다.

## 먼저 연결할 공통 부분

- 개발 중 프론트는 Vite 프록시를 통해 `/api/...`로 요청한다. 현재 [`frontend/src/api.ts`](../../frontend/src/api.ts)의 `api()`는 모든 요청에 `Content-Type: application/json`을 붙인다. 사진·음성의 `FormData` 요청은 별도 업로드 함수를 만들고 **Content-Type을 직접 지정하지 않는다**. 브라우저가 multipart boundary를 붙여야 한다.
- `POST /api/families` 또는 `/api/families/join`이 돌려준 `access_token`을 새 가족방의 후속 요청에 `Authorization: Bearer <access_token>`으로 보낸다. 토큰이 빠지면 현재 로컬 설정에서는 **기존 `demo-family`가 열리므로**, 새 가족방의 데이터가 안 보이는 원인이 된다. `GET /api/families/me`의 `member.id`와 `authenticated`로 현재 사용자를 확인한다. 로컬에서 `LGDX_REQUIRE_AUTH=1`을 켜면 무토큰 요청은 401이다.
- 오류 `detail`은 문자열 또는 `{ "code": "...", "message": "..." }`이다. 상태 코드만으로 한도·구독·외부 API 오류를 섞어 표시하지 말고 `detail.code`를 읽는다. OpenAI 키, `.env`, 개발자 토큰은 프론트 코드나 브라우저 저장소에 넣지 않는다.
- 현재 화면의 임의 `viewer` 전환은 서버 로그인 사용자 전환이 아니다. 새 가족방에서는 토큰의 구성원 ID를 기준으로 버튼 권한과 데이터 표시를 결정한다. 기존 ThinQ 계정 로그인과 가족방 세션 연결은 아직 별도 작업이다.
- 인증된 가족방의 `/api/bootstrap`은 현재 구성원에게 해당하는 DB 알림만 반환하고, 다른 구성원의 개인 일정 제목은 `바쁨`으로 가린다. 화면에서 다른 구성원의 제목을 캐시하거나 데모 가족 데이터와 섞지 않는다.

## 화면별 연동 계약

| 기존 화면·지점 | 사용할 API와 요청 | 응답을 화면에 반영할 방식 |
|---|---|---|
| `chat` 입력·추천 질문 | `POST /api/assistant/chat` JSON `{ "message": "오늘 담당 배정은?" }`; `GET /api/assistant/history` | 현재 `chatReply()`를 호출하는 입력·추천 질문 모두 서버 `answer`로 교체한다. 응답의 `usage.total_tokens`, `usage.used_today`, `plan`을 사용량 표기에 쓰고, 기록의 `messages[]`를 새로고침 후 복원한다. 답변에는 실제 일정·돌봄 항목·배정이 서버에서 제공되며 AI가 배정을 직접 변경하지 않는다. **Free도 채팅 가능**하고 하루 10,000 토큰 제한이 있다. |
| `chat` 음성 아이콘 | 녹음/파일 선택으로 얻은 `File`을 `POST /api/assistant/voice`의 multipart `file`로 업로드 | 응답의 `transcript`를 사용자 말풍선, `answer`를 AI 말풍선으로 표시한다. 별도 받아쓰기만 필요하면 `POST /api/audio/transcribe`에 `file`과 `purpose=CHAT`을 보낸다. 현재 아이콘은 `<img>`뿐이라 PC·모바일 마이크 권한 요청, 녹음 시작·정지·업로드 UI가 필요하다. WAV/MP3/M4A/OGG/WebM, 최대 20 MiB. |
| `capture` 촬영·앨범 선택 | 선택한 **실제 `File`**을 유지하고 `POST /api/intakes/photo` multipart `file`, 선택한 `child_id`, `source=CAMERA` 또는 `ALBUM`으로 전송 | 201 응답의 `transcript`, `items[]`, `requires_review`, `ocr_used_today`를 보여주고 기존 `review` 화면에서 항목을 수정·확인한다. JPEG/PNG/WebP, 최대 10 MiB. 현재 `captureFile`은 파일명만 저장하고 사진은 로컬 미리보기여서 OCR이 호출되지 않는다. 수기 입력은 기존 JSON `POST /api/intakes`를 유지한다. |
| `onboarding`·`members` 가족방 | 주돌봄자: `POST /api/families` JSON `name`, `owner_name` → `family_id`, `member_id`, `invite_code`, `invite_expires_at`, `access_token`, `plan`; 초대받은 사람: `POST /api/families/join` JSON `invite_code`, `name`, `role=PARENT\|GRANDPARENT\|CAREGIVER` → 가족·구성원 ID와 토큰. 주돌봄자는 `POST /api/families/invite-code/rotate` 가능 | 새 가족방 생성 직후 10자리 초대코드와 만료시각(7일)을 보여주고, 참가자는 코드 입력 후 받은 토큰으로 `/api/bootstrap`을 다시 읽는다. 방 생성자의 역할은 현재 서버에서 `PARENT`로 고정된다. `mom`, `jiu`, `grandma` 같은 데모 고정 ID는 새 방의 실제 ID로 바꾼다. Free 가족방은 구성원 3명까지다. |
| `plan`·Free/Pro 상태 | `GET /api/plans`, `GET /api/subscription`, `GET /api/features`; 새 가족방은 bearer 토큰 포함 | `plans[].status`의 `PRO=AVAILABLE`은 **상품 출시 상태**이며 `/subscription`의 `NOT_SUBSCRIBED`는 **현재 가족 미구독 상태**다. `/features`의 `available`은 요금제 사용 권한, `backend_state`는 실제 백엔드 준비 상태다. 브라우저 `localStorage`의 체험 스위치는 서버 구독을 바꾸지 않는다. 로컬 개발자 플랜 미리보기는 `/api/dev/preview-plan`과 비공개 `X-Developer-Token`을 사용하는 **수동 서버 테스트**로만 다룬다. 결제 검증 API는 아직 없다. |
| `tasks` 완료·`handoff` 특이사항 | 기존 `POST /api/assignments/{id}/complete` JSON `{ "note": "..." }`; 확인 전 인수인계는 `PATCH /api/handoffs/{id}` JSON `{ "special_note": "..." }`; 다음 담당 지정은 `POST /api/assignments/{id}/handoff` JSON `to_member_id`, 선택 `special_note`, `briefing` | 완료 메모가 있고 담당자가 주돌봄자가 아니면 주돌봄자에게 `PENDING` 인수인계가 자동 생성된다. `GET /api/bootstrap`의 `handoffs[]`에 `special_note`가 있으므로 프론트 `Handoff` 타입과 화면에 추가한다. `acknowledge` 버튼은 **토큰의 구성원 ID가 `to_member_id`인 경우**만 보여준다. |
| `emergency` 요청 미리보기 | Pro 부모가 `POST /api/emergency-requests` JSON `assignment_id`, 선택 `reason`; `GET /api/emergency-requests`; 자격이 있는 다른 구성원은 `POST /api/emergency-requests/{id}/claim`; 요청자/주돌봄자는 `POST /api/emergency-requests/{id}/cancel` | `PROPOSED`/`ACCEPTED` 배정만 선택하도록 한다. 생성 응답의 `request`, `recipient_member_ids`와 조회 `requests[]`의 `OPEN`/`CLAIMED`/`CANCELLED` 상태를 표시한다. 선착순 `claim`만 새 `ACCEPTED` 배정과 인수인계를 만들며, 이후 응답은 409다. **DB 알림 기록은 생기지만 ThinQ 푸시는 아직 없다.** |

채팅 응답의 핵심 형태는 `{ "message": "...", "answer": "...", "usage": { "total_tokens": 123, "used_today": 456 }, "plan": "FREE", "requires_confirmation_for_actions": true }`이다. `/api/assistant/voice`에는 같은 필드와 `transcript`가 추가된다. 사진 응답은 기존 `/api/intakes`의 `intake_id`, `items`, `requires_review`에 `transcript`, `source`, `ocr_used_today`가 추가된다. `usage` 숫자는 예시이며 실제 사용량은 서버 응답을 따른다.

## 오류와 아직 없는 기능

| 경우 | HTTP / `detail.code` | 프론트 처리 |
|---|---|---|
| Free 채팅 하루 한도 | 403 / `CHAT_DAILY_LIMIT` | 오늘 사용량을 보여주고 다음 날 또는 Pro 구독 안내 |
| Free OCR 하루 2회 성공 한도 | 403 / `OCR_DAILY_LIMIT` | 수기 입력 대안과 사용량 안내; OCR 실패는 성공 횟수에 넣지 않음 |
| Pro 전용 기능 미구독 | 403 / `SUBSCRIPTION_REQUIRED` | Pro는 출시됨; 현재 가족의 구독 상태 안내 |
| Free 가족방 인원 한도 | 403 / `PLAN_LIMIT` | 초대 참가 실패와 한도 안내 |
| OpenAI API 미설정·크레딧 소진·키 거부·요청 제한 | 503 / `AI_NOT_CONFIGURED`·`OPENAI_CREDITS_EXHAUSTED`·`OPENAI_KEY_REJECTED`, 429 / `OPENAI_RATE_LIMITED` | 앱 구독 오류로 오해하지 말고 서버 운영 오류로 표시. 비밀 키를 화면에 노출하지 않음 |
| 토큰 무효 또는 인증 필수 설정에서 누락, 파일 문제, 종료된 요청 | 401, 413/415/422, 409 | 각각 재인증·파일 재선택·최신 요청 상태 재조회 |

`voice_schedule`·`voice_emergency`는 **음성→텍스트까지만** 있고 일정 생성·긴급 요청 자동 실행은 없다. Google/Outlook 캘린더 OAuth, ThinQ 가전/푸시 연결, 서버 앨범, 돌봄 공백·지역 제도 API, 실제 결제/구독 검증도 아직 없다. `/api/features`의 `backend_state=PARTIAL` 또는 `NOT_CONNECTED`를 보고 목업을 실제 기능으로 표기하지 않는다. 카메라/앨범 선택과 마이크 녹음은 기기·브라우저에서 프론트가 수행하고, 서버는 전달된 파일을 분석한다.

## 연동 확인 순서

1. 백엔드 `http://127.0.0.1:8000/docs`와 프론트 `http://127.0.0.1:5173`를 실행한다. 현재 로컬에서 **실제 OpenAI 채팅과 PC에서 만든 WAV 파일→음성인식→AI 답변 모두 200**으로 확인했다. 백엔드 테스트 11개가 통과했다. API 키는 각 개발자의 `backend/.env`에 따로 넣고 저장소에는 올리지 않는다.
2. 새 가족방 생성 후 토큰을 붙인 `/api/families/me`가 `authenticated=true`, `/api/bootstrap`의 `family.id`가 생성 응답의 `family_id`인지 확인한다. 토큰을 빼고 데모 가족이 보이는 실수를 점검한다.
3. 화면에서 사진 파일을 실제 업로드해 `transcript`와 확인 대기 항목을 보고, 텍스트 수기 등록도 계속 동작하는지 확인한다.
4. 입력·추천 질문·PC 마이크 또는 녹음 파일 모두 서버 답변으로 표시되는지, 새로고침 뒤 채팅 기록이 복원되는지 확인한다. 403 한도·503 OpenAI 운영 오류는 서로 다른 안내로 표시한다.
5. 구성원별 토큰으로 인수인계 수신자 버튼과 긴급 요청 선착순 응답을 확인한다. Free/Pro 화면 상태는 `localStorage`가 아니라 서버 조회 결과를 따른다.

백엔드 구현의 상세 실행법은 [backend/README.md](../../backend/README.md), 기존 수기 돌봄 API는 [개발 계약](../개발_계약.md), 실행 중 실제 요청 스키마는 `http://127.0.0.1:8000/openapi.json`을 참고한다.
