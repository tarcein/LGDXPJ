## 프론트 연동 현황 (2026-09-17)

- 완료: `홈 · 케어 · 일정 · 가족 · 더보기` 5탭과 `bar_asset` 선택 색상, 상단 알림·프로필, 플로팅 AI 채팅, 가족방 생성·재사용 초대 링크 참가와 Bearer 세션, 아이를 지정하는 사진 OCR·수기 일정 등록, 월간 달력 일정명·아이별 색상·담당자·필터, 날짜 상세→아이/본인 선택→일정 등록 흐름, 직접 시간 입력과 주간 반복 루틴 일괄 등록, AI 텍스트·음성 채팅·요약 카드·일정 변경 및 기록 복원, 서버 플랜·기능 조회, 토스 자동결제 카드 등록과 첫 달 결제, 긴급 요청 생성·응답·취소, 완료 체크 안의 수기·음성·사진 인수인계, 날짜 폴더 기반 패밀리 앨범·사진 확대·다운로드, 구성원별 시·도/시·군·구 기반 보조금24 돌봄 제도·아이돌봄 제공기관·소득 및 건강보험료 기준 조회.
- 초대 링크는 `GET /api/families/invitations/{invite_code}`로 가족방·방장·만료일을 먼저 확인한다. 같은 링크는 만료·폐기·사용 횟수 제한 전까지 여러 구성원이 반복해서 사용할 수 있다. 프론트는 초대 안내, 기본 정보, 기능 소개의 3단계를 거쳐 참가 API를 호출한다.
- `backend/.env`의 `DATABASE_URL`을 사용해 PostgreSQL 서버로 전환했고 기존 `backend/lgdx.db` 데이터도 이관했다. `DATABASE_URL`이 없거나 테스트에서 `LGDX_DB_PATH`를 지정하면 SQLite를 사용한다.
- 아이 일정을 등록하면 각 일정에 연결된 배정용 `care_item`을 자동 생성하고 첫 `care_item_id`로 추천 화면을 연다. 추천은 요청자 본인을 제외하고 개인 일정 충돌·동시간 돌봄·진행 중 배정 수를 비교한다.
- 배정 요청 알림은 수신 구성원에게만 저장되고 `action_type`, `action_id`로 해당 배정 상세·수락·거절 화면을 연다. 앱 실행 중에는 10초 간격 동기화와 브라우저 시스템 알림을 사용한다. 앱이 완전히 닫힌 상태의 Web Push는 HTTPS·서비스 워커·VAPID 설정이 추가로 필요하다.
- 구성원은 `POST /api/families/leave`로 나갈 수 있고, 주돌봄자는 `POST /api/members/{id}/remove`로 다른 구성원을 퇴장시킨다. 해당 세션은 즉시 폐기된다. 주돌봄자 이전은 아직 없어 방장은 탈퇴할 수 없다.
- 새 가족방의 아이 정보는 가족 설정에서 등록한다. 인증된 사용자는 본인의 할 일·일정만 조작하고, 정보 공개 변경은 주돌봄자에게만 제공한다.
- Google/Outlook 개인 캘린더는 OAuth 연결·콜백·동기화 API까지 구현했다. 현재 로컬 `.env`에는 두 제공자의 Client ID/Secret이 모두 잡혀 연결 버튼이 활성화된다. 실제 로그인 완료를 위해 각 제공자 콘솔에 `CALENDAR_REDIRECT_BASE` 기준 콜백 URI가 정확히 등록되어 있어야 한다.
- 남은 작업: Toss 운영 심사·키 설정과 월별 재결제 스케줄러·웹훅·해지/환불, 빌링키 암호화, ThinQ 계정과 가족방 세션 연결, 닫힌 앱 푸시·가전, 돌봄 공백 예측 고도화. 개발자 플랜 전환은 브라우저에 비밀 토큰을 넣지 않고 백엔드 개발 모드로 시험한다.

## 먼저 연결할 공통 부분

- 개발 중 프론트는 Vite 프록시를 통해 `/api/...`로 요청한다. 현재 [`frontend/src/api.ts`](../../frontend/src/api.ts)의 `api()`는 모든 요청에 `Content-Type: application/json`을 붙인다. 사진·음성의 `FormData` 요청은 별도 업로드 함수를 만들고 **Content-Type을 직접 지정하지 않는다**. 브라우저가 multipart boundary를 붙여야 한다.
- `POST /api/families` 또는 `/api/families/join`이 돌려준 `access_token`을 새 가족방의 후속 요청에 `Authorization: Bearer <access_token>`으로 보낸다. 토큰이 빠지면 현재 로컬 설정에서는 **기존 `demo-family`가 열리므로**, 새 가족방의 데이터가 안 보이는 원인이 된다. `GET /api/families/me`의 `member.id`와 `authenticated`로 현재 사용자를 확인한다. 로컬에서 `LGDX_REQUIRE_AUTH=1`을 켜면 무토큰 요청은 401이다.
- 오류 `detail`은 문자열 또는 `{ "code": "...", "message": "..." }`이다. 상태 코드만으로 한도·구독·외부 API 오류를 섞어 표시하지 말고 `detail.code`를 읽는다. OpenAI 키, `.env`, 개발자 토큰은 프론트 코드나 브라우저 저장소에 넣지 않는다.
- 현재 화면의 임의 `viewer` 전환은 서버 로그인 사용자 전환이 아니다. 새 가족방에서는 토큰의 구성원 ID를 기준으로 버튼 권한과 데이터 표시를 결정한다. 기존 ThinQ 계정 로그인과 가족방 세션 연결은 아직 별도 작업이다.
- 인증된 가족방의 `/api/bootstrap`은 현재 구성원에게 해당하는 DB 알림만 반환하고, 다른 구성원의 개인 일정 제목은 `바쁨`으로 가린다. 화면에서 다른 구성원의 제목을 캐시하거나 데모 가족 데이터와 섞지 않는다.

채팅 응답의 핵심 형태는 `{ "message": "...", "answer": "...", "cards": [{ "eyebrow": "오늘", "title": "일정 제목", "description": "시간·담당자", "screen": "schedule" }], "schedule_changes": [], "usage": { "total_tokens": 123, "used_today": 456 }, "plan": "FREE" }`이다. `/api/assistant/voice`에는 같은 필드와 `transcript`가 추가된다. 사진 응답은 기존 `/api/intakes`의 `intake_id`, `items`, `requires_review`에 `transcript`, `source`, `ocr_used_today`가 추가된다. `usage` 숫자는 예시이며 실제 사용량은 서버 응답을 따른다.

## 오류와 아직 없는 기능

| 경우 | HTTP / `detail.code` | 프론트 처리 |
|---|---|---|
| Free 채팅 하루 한도 | 403 / `CHAT_DAILY_LIMIT` | 오늘 사용량을 보여주고 다음 날 또는 Pro 구독 안내 |
| Free OCR 하루 2회 성공 한도 | 403 / `OCR_DAILY_LIMIT` | 수기 입력 대안과 사용량 안내; OCR 실패는 성공 횟수에 넣지 않음 |
| Pro 전용 기능 미구독 | 403 / `SUBSCRIPTION_REQUIRED` | Pro는 출시됨; 현재 가족의 구독 상태 안내 |
| Free 가족방 인원 한도 | 403 / `PLAN_LIMIT` | 초대 참가 실패와 한도 안내 |
| OpenAI API 미설정·크레딧 소진·키 거부·요청 제한 | 503 / `AI_NOT_CONFIGURED`·`OPENAI_CREDITS_EXHAUSTED`·`OPENAI_KEY_REJECTED`, 429 / `OPENAI_RATE_LIMITED` | 앱 구독 오류로 오해하지 말고 서버 운영 오류로 표시. 비밀 키를 화면에 노출하지 않음 |
| 토큰 무효 또는 인증 필수 설정에서 누락, 파일 문제, 종료된 요청 | 401, 413/415/422, 409 | 각각 재인증·파일 재선택·최신 요청 상태 재조회 |

`voice_schedule`·`voice_emergency`는 **음성→텍스트까지만** 있고 일정 생성·긴급 요청 자동 실행은 없다. Google/Outlook의 로컬 OAuth 설정은 모두 감지됐고 인증 URL 생성 테스트까지 통과했지만, 실제 계정의 로그인·동의와 공급자 콘솔 콜백 등록은 개발자 계정에서 최종 확인해야 한다. ThinQ 가전/닫힌 앱 푸시 연결, 돌봄 공백 예측과 Toss 운영 환경의 정기 재결제·웹훅·해지/환불은 아직 없다. 현재 결제 구현은 카드 등록, 빌링키 발급, 첫 달 결제와 Pro 활성화까지다. 카메라/앨범 선택과 마이크 녹음은 기기·브라우저에서 프론트가 수행하고, 서버는 전달된 파일을 분석한다. LAN의 HTTP 주소에서는 브라우저 직접 마이크가 차단되므로 파일 선택 우회 없이 안내를 표시한다. 휴대폰 음성 시험은 `start-secure-phone.ps1`의 임시 HTTPS 주소를 사용한다.

## 연동 확인 순서

1. 백엔드 `http://127.0.0.1:8000/docs`와 프론트 `http://127.0.0.1:5173`를 실행한다. 현재 자동화 백엔드 테스트 31개, 프론트 빌드·린트, 모바일 연결 화면 검증이 통과했다. API 키와 OAuth 비밀값은 각 개발자의 `backend/.env`에 따로 넣고 저장소에는 올리지 않는다.
2. 새 가족방 생성 후 토큰을 붙인 `/api/families/me`가 `authenticated=true`, `/api/bootstrap`의 `family.id`가 생성 응답의 `family_id`인지 확인한다. 토큰을 빼고 데모 가족이 보이는 실수를 점검한다.
3. 화면에서 사진 파일을 실제 업로드해 `transcript`와 확인 대기 항목을 보고, 텍스트 수기 등록도 계속 동작하는지 확인한다.
4. 입력·추천 질문·PC 마이크 또는 녹음 파일 모두 서버 답변으로 표시되는지, 새로고침 뒤 채팅 기록이 복원되는지 확인한다. 403 한도·503 OpenAI 운영 오류는 서로 다른 안내로 표시한다.
5. 구성원별 토큰으로 인수인계 수신자 버튼과 긴급 요청 선착순 응답을 확인한다. Free/Pro 화면 상태는 `localStorage`가 아니라 서버 조회 결과를 따른다.
6. Google에는 `{CALENDAR_REDIRECT_BASE}/api/calendar-connections/google/callback`, Microsoft에는 `{CALENDAR_REDIRECT_BASE}/api/calendar-connections/microsoft/callback`을 웹 리디렉션 URI로 등록하고 연결·동기화를 각각 검증한다.
7. 돌봄 제도 화면에 `서울특별시`, `은평구`를 저장한 뒤 구 사업·시 사업·전국 공통 배지가 나뉘고 다른 시군구 전용 사업이 섞이지 않는지 확인한다.

백엔드 구현의 상세 실행법은 [backend/README.md](../../backend/README.md), 기존 수기 돌봄 API는 [개발 계약](../개발_계약.md), 실행 중 실제 요청 스키마는 `http://127.0.0.1:8000/openapi.json`을 참고한다.
