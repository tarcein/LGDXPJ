# 개발 범위와 API 계약

이 문서는 [기능 요구사항](기능요구사항명세서.md), [메뉴 구조](메뉴구조도다이어그램/메뉴구조도.md), [데이터 객체 정의](LG_가족_운영_에이전트_데이터객체정의서_완성.md)를 개발 작업으로 연결합니다. Figma `기능` 페이지의 화면 묶음은 360×740 모바일 캔버스, 밝은 배경 `#F4F6FC`, 주요 동작 `#C4123F`를 기준으로 구현했습니다.

## 상태와 데이터 경계

`care_item`은 `NEEDS_REVIEW` → `CONFIRMED` → `ASSIGNED` → `DONE`으로 이동합니다. 미확인 항목은 배정할 수 없습니다. `care_assignment`는 `PROPOSED` → `ACCEPTED` 또는 `REJECTED` → `COMPLETED`로 이동합니다. 제안은 수락 전까지 확정으로 표시하지 않습니다. `care_handoff`는 담당자 수락 후 `PENDING`으로 생성되고, 다음 담당자가 확인하면 `ACKNOWLEDGED`가 됩니다. 예외 승인 시 기존 배정은 `CANCELED`, 대체 배정은 새 `PROPOSED` 요청으로 시작합니다.

새 돌봄 항목의 예정 일시는 `review`에서 수기로 확인해 입력합니다. 입력한 시각은 담당 후보의 개인 일정과 비교되며, 미입력 항목은 시간 충돌을 판정할 수 없습니다.

프로토타입은 `demo-family` 하나로 고정하고 SQLite에 가상의 지우·하윤 가족을 시드합니다. 논리 테이블 이름은 데이터 객체 정의서의 PostgreSQL 물리명과 맞췄습니다. 운영 DB와 인증을 붙일 때는 API 응답 키를 유지하면서 저장소를 교체합니다.

## HTTP API

모든 요청·응답은 JSON입니다. 오류는 `detail`로 반환됩니다. 개발 중 `/api`는 Vite 프록시를 통과합니다.

| 동작 | 경로 | 요청 핵심 필드 |
|---|---|---|
| 초기 화면 데이터 | `GET /api/bootstrap` | 없음 |
| 아이·구성원 추가 | `POST /api/children`, `POST /api/members` | `name`, `age_label` / `name`, `role` |
| 개인 일정 등록 | `POST /api/schedules` | `member_id`, `title`, `starts_at`; `ends_at` 선택, 반복은 `repeat_days`·`repeat_until` 또는 `repeat_dates` |
| 개인 일정 수정 | `PATCH /api/schedules/{id}` | 변경 필드, `update_scope`: 선택 일정만 `SINGLE` / 해당 일정 이후 반복 일정 `FUTURE` |
| 아이 일정 등록 | `POST /api/child-schedules` | `child_id`, `title`, `category`, `starts_at`; `ends_at` 선택, 반복 필드 동일 |
| 아이 일정 수정 | `PATCH /api/child-schedules/{id}` | 변경 필드, `update_scope`: 선택 일정만 `SINGLE` / 해당 일정 이후 반복 일정 `FUTURE` |
| 돌봄 정보 등록 | `POST /api/intakes` | `child_id`, `raw_content`, `input_type` |
| 확인 전 수정 | `PATCH /api/items/{id}` | `title`, `detail`, `item_type`, `starts_at` 중 필요한 값 |
| 항목 확인 | `POST /api/items/{id}/confirm` | 없음 |
| 담당 후보 | `GET /api/items/{id}/suggestions` | 없음 |
| 배정 요청 | `POST /api/assignments` | `item_id`, `assignee_id`, `source` |
| 배정 수락·거절 | `POST /api/assignments/{id}/respond` | `decision`: `ACCEPTED` / `REJECTED` |
| 완료·특이사항 | `POST /api/assignments/{id}/complete` | `note` |
| 인수인계 확인 | `POST /api/handoffs/{id}/acknowledge` | 없음 |
| 예외 대안 | `POST /api/exceptions`, `POST /api/exceptions/{id}/approve` | `assignment_id`, `alternative_member_id`, `reason` |
| 알림 읽음 | `PATCH /api/notifications/{id}/read` | 없음 |
| 공개 범위 | `PATCH /api/members/{id}/permissions` | `scope`, `is_allowed` |
| 앱 알림 설정 | `PATCH /api/members/{id}/notification-preferences` | `app_enabled`, `daily_digest_enabled` |

요청 형식의 상세 스키마는 실행 중 `http://127.0.0.1:8000/openapi.json`에 자동 생성됩니다. 프론트 타입은 `frontend/src/api.ts`에 있습니다. API 키 이름이나 상태를 바꾸는 변경은 프론트·백엔드 팀이 이 문서와 타입을 함께 갱신해야 합니다.

## 다음 연동 작업

백엔드는 OCR/STT 공급자, ThinQ 인증·푸시, 외부 캘린더 OAuth, 결제 사업자, 위치 동의·보관기간, 실제 LLM 호출을 각각 별도 어댑터로 붙여야 합니다. 인증 전에는 가족 ID나 구성원 ID를 요청만으로 신뢰해서는 안 됩니다. 프론트엔드는 Figma의 세부 상태 화면과 접근성을 이어 다듬고, 연동 오류·동의·권한 화면을 추가해야 합니다. 실제 아동·위치·건강 데이터는 인증, 권한 검사, 암호화, 삭제 정책이 완성되기 전에는 사용하지 않습니다.
