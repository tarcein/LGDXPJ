# ZIPPY 메뉴구조도

`docs/메뉴구조도.md`를 기준으로 생성한 사용자 관점의 계층형 정보구조 다이어그램이다. 시스템 내부 처리, API, DB, 버튼, 입력 항목은 포함하지 않고 앱에서 접근하는 메뉴와 화면만 표현했다.

## 생성 파일

- `00_전체_메뉴구조도.mmd` — S1~S19 전체 메뉴·화면 구조
- `00_전체_메뉴구조도.png` — 전체 메뉴구조도 렌더링 결과
- `01_MVP_메뉴구조도.mmd` — MVP 핵심·MVP 필수 기반만 포함한 구조
- `01_MVP_메뉴구조도.png` — MVP 메뉴구조도 렌더링 결과
- `README.md` — 산출물 설명과 범례

## Depth 정의

- Root: `ZIPPY`
- 1Depth: 홈, 일정, 돌봄, 알림, 가족, 혜택·부가 서비스, 계정
- 2Depth: 각 1Depth 아래의 목적별 메뉴
- 화면: 최종 접근 화면. 이 기준 문서에는 3Depth 메뉴가 별도로 정의되지 않은 항목이므로 2Depth에서 화면으로 직접 연결했다.

## 화면 표기 방식

최종 화면 노드는 다음 순서로 표기했다.

`화면명 | SCR-01~SCR-21 | 주요 FR ID`

화면 ID는 기능요구사항명세서의 S1~S21을 현재 요청의 규칙에 따라 `SCR-01`~`SCR-21`로 변환했다. S15(돌봄 동선 확인)는 서비스 범위에서 제외되어 결번이며, S20·S21(준비물 확인·숙제 확인)은 Family Inbox에서 분리된 화면으로 이후 추가됐다.

## 기준 및 확인 사항

- 가독성을 위해 각 1Depth를 하나의 세로 행으로 쌓고, 하위 메뉴와 화면은 해당 행 안에서 좌→우로 연결했다. 돌봄처럼 하위 메뉴가 많은 영역은 두 행으로 나눠 가로 폭을 줄였다.
- 메뉴명, Depth, 화면명은 `docs/메뉴구조도.md`의 계층 구조와 화면 레지스트리를 기준으로 사용했다.
- 기능요구사항 ID는 `docs/기능요구사항명세서.md`에서 해당 화면의 주요 항목만 간결하게 매핑했다.
- `docs/메뉴구조도.md` 본문에는 기존에 `SCR-001` 형식이 일부 기록되어 있으나, 이번 생성 요청의 명시 규칙인 `SCR-01` 형식을 다이어그램에 적용했다.
- PNG는 각 `.mmd` 원문을 Mermaid CLI로 직접 렌더링한 결과다.
